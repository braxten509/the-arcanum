# Phase 0 — 🚦 GATE: six course-shaping questions (NEVER skip)

Read **§0** and **§6 step 0**. Collect all six gate answers: prior knowledge,
starting level, project scope, lesson depth, mastery, and tooling. **WAIT for the user's
real answers.** The
**Tooling** answer (internal / external / both) is expanded inside the plan's
**Calibration contract** — obey it: it decides whether `externalWorkspace` is allowed
and whether the real external tools must be taught. Starting level and mastery are
independent: starting level controls the opening explanations; mastery controls how independently
the learner must use the course's declared implementation language after scaffolding fades.
For Start 1–3, starting level also controls lesson density: Start 1 is deliberately low-density,
Start 2 uses moderate density, and Start 3 may use dense but coherent lessons after prerequisites
are secure. Lesson depth controls thoroughness and edge cases, not cognitive-load packaging.
Project scope is a separate 1–5 artifact-size axis: 1 is a barely functional proof project and
5 is the broadest feasible full-fledged project. It changes the finished artifact's systems,
content, polish, and delivery—not the required language breadth. Lesson depth may add detail, but
the selected mastery enforces its own minimum depth floor.
At Mastery 1, the project is primary and the course teaches the minimum language needed while the
learner writes the code. At Mastery 2, the project remains primary but the course deliberately
teaches useful general language areas. At Mastery 3–5, language mastery is primary and the project
is its cumulative practice and proof vehicle. Mastery also selects the versioned language coverage
profile; Project Scope cannot remove an area from it. The generated
Calibration contract expands each mastery number into concrete graded language evidence; later
phases must follow that exact text.

This gate is absolute. **Even in an autonomous / automode run, interrupt the run and
ask** — you can break out of automode, so do it. Never answer for the user, never
assume defaults, never proceed unanswered.

→ **Produce:** the user's six answers. Nothing else exists until they arrive.
