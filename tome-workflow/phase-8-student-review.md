# Phase 8 — Student review & gap-fill (mandatory)

Reconcile omissions and contradictions, then prove the course as a first-time learner.
Follow the harness review scope, assume only declared prerequisites, and never bridge a gap
with reviewer expertise.

Audit these semantic contracts:

1. **Cross-section agreement.** Track every recurring identifier, API, type, file path,
   command, data shape, behavior, and instruction from its first owner through later
   consumers. Intentional replacement must update every dependent lesson, exercise,
   reading, hint, rubric, and capstone.
2. **Cumulative source truth.** Compare repeated files and types with their prior complete
   versions. Replacements retain required imports, members, behavior, and wiring; patches
   name the file and exact insertion point. Reconstruct the artifact forward from lesson
   one and backward from acceptance.
3. **Learner execution.** Follow the instructions in order in a disposable workspace and
   run meaningful milestones with the real toolchain. Any required deletion, insertion
   point, value, asset, working directory, recovery action, or API left to inference is a
   blocking gap.
4. **Capability proof.** Trace each freestyle requirement through `requires` to its owning
   `teaches`, then inspect that lesson for the complete code or procedure. Matching ids,
   names, handoffs, or plan claims are not teaching evidence.
5. **Runtime agreement.** Compare `[runtime]`, its selected global runtime, and all lessons:
   language, entry file, starter, scaffold, run/build/check behavior, diagnostics,
   extensions, editor mode, and external-workspace assumptions. Inspect other consumers
   before editing a shared runtime and exercise the resolved runtime after a change.
6. **Continuity and lifecycle.** Verify handoff and plan claims against files. Retire or
   deliberately ship every temporary fixture, prompt, demo mutation, mock, placeholder,
   and debug path. Cold-start the final entrypoint and trace visible behavior, persistence,
   relaunch, and delivery.
7. **Calibration and independence.** Enforce every Phase 0 answer and treat prior knowledge
   as exhaustive. At Start 1–3, each unlisted keyword, syntax form, operator, API, tool
   action, or technical term needs, before required use, a plain-language purpose,
   stepwise anatomy, a minimal worked example with an observable result, one likely
   failure, and guided practice. A name-drop, reading link, or unexplained sample is not
   teaching; Start 2 permits less repetition, not skipped fundamentals. For
   `externalWorkspace`, require the complete novice tool and delivery loop. Fail hollow
   late chapters, unavailable assets, or an unachievable `meta.description`.

Resolve intended behavior from the approved arc, `meta.description`, acceptance journey,
and observed runtime—not majority wording. Repair any authored tome file or its selected
runtime configuration. Follow the exact verdict/findings protocol: one invocation is one
review-or-repair pass, and a later fresh pass must verify every repair before `PASS`.
