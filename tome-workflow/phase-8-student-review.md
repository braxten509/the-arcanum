# Phase 8 — Student review & gap-fill (mandatory)

Read `tome-authoring/9-proof-and-assets.md` and `tome-authoring/10-mastery-evidence.md`.
Reconcile contradictions, then prove the course
as a first-time learner using only declared prerequisites. You are the same continuous author,
so compensate deliberately for familiarity: execute the written path from a clean workspace,
trust artifacts and output over memory, and treat every missing learner step as blocking.

Audit these semantic contracts:

1. **Cross-section agreement.** Track every recurring identifier, API, type, file path,
   command, data shape, behavior, and instruction from its first owner through later
   consumers. Intentional replacement must update every dependent lesson, exercise,
   reading, hint, rubric, and capstone.
2. **Cumulative source truth.** Compare repeated files and types with prior complete versions.
   Replacements retain required imports, members, behavior, and wiring; patches name the
   file and insertion point. Reconstruct forward from lesson one and backward from acceptance.
3. **Learner execution.** Follow instructions in a disposable workspace and run meaningful
   milestones with the real toolchain. Paths, behavioral requirements, constraints, commands,
   diagnostics, and observable checks must be explicit; implementation and design choices that
   the Working deliberately assigns to the learner must not be pre-decided. Open the validator's
   exact `.tome-build/<tome-id>.learner-project`; do not mentally compose cumulative edits.
4. **Capability proof.** Trace each freestyle requirement through `requires` to its owning
   `teaches`, then inspect that lesson for a complete disposable example or taught procedure.
   Matching ids, names, handoffs, or plan claims are not teaching evidence, and a canonical
   project solution is answer leakage rather than stronger teaching.
5. **Runtime agreement.** Compare `[runtime]`, its selected global runtime, and all lessons:
   language, entry file, starter, scaffold, run/build/check behavior, diagnostics,
   extensions, editor mode, and external-workspace assumptions. Inspect other consumers
   before editing a shared runtime and exercise the resolved runtime after a change.
   Recheck the dependency installability rule against the selected runtime's actual interpreter or
   toolchain version and target platform. Provision the exact declared specs through its isolated
   package command; fail a guessed, unavailable, or runtime-incompatible pin even when a different
   version of the package happens to exist on the authoring host.
6. **Continuity and lifecycle.** Verify handoff and plan claims against files. Retire or
   deliberately ship every temporary fixture, prompt, demo mutation, mock, placeholder,
   and debug path. Cold-start the final entrypoint and trace visible behavior, persistence,
   relaunch, and delivery.
   Inspect the proof-evidence matrix's actual command/output rows and fingerprint, including the
   ordinary no-flag launch and every negative challenge. Green is a prerequisite, not proof of
   semantics. Verify acceptance drives real public or domain behavior; controls may inject input,
   clock, seed, or frame limit, but not directly assign the promised outcome or saved state.
7. **Calibration.** Enforce every Phase 0 answer and treat prior knowledge
   as exhaustive. Apply the plan's current Calibration contract over any older paraphrase
   without changing the user's recorded number. At Start 1–3, each unlisted
   keyword, syntax form, operator, API, tool
   action, or technical term needs, before required use, a plain-language purpose,
   stepwise anatomy, a minimal worked example with an observable result, one likely
   failure, and guided practice. A name-drop, reading link, or unexplained sample is not
   teaching. Enforce the plan's exact `Lesson pacing` line: Start 1 uses one foundational
   concept family per lesson, Start 2 uses one major family plus tightly related support, and
   Start 3 may use dense lessons only for closely related families after prerequisites are
   secure. Fail bundled independently teachable foundations or a broad mechanism label that
   conceals excessive density. Three lessons is a schema minimum, not a planning default; fail a
   section whose real dependency load was compressed instead of using the available lesson capacity
   or an earlier Arc split. Perform a cold-start dependency walk through every Working's brief,
   artifacts, rubric, proof, validation, and hidden replay. Fail any language mechanism, library or
   runtime API, tool action, configuration or data-format rule, or technical term required before
   its owner. Foundational language mechanisms must precede dependent runtime, library, tooling,
   configuration, and integration work. Allow setup before foundations only when it is behavior-
   free, mechanically followable, and requires no learner-authored source, configuration,
   entrypoint, or integration using untaught mechanisms. Also fail a mechanism introduced merely
   because it was next in a catalog rather than because it materially enables its section's
   Working, as well as a near-duplicate later label that conceals an earlier use. Start 2 permits
   less repetition, not skipped fundamentals. Expand each mechanism through the prerequisites of
   its smallest meaningful example; fail when an unlisted construct, API, action, format rule, or
   term appears before an earlier owner, even if the learner could copy it blindly. Trace how API
   inputs/resources are created, obtained, and released. Apply observable-interaction closure to
   every promise, Working, acceptance path, and control: fail when the concrete operations needed
   to obtain and inspect input, produce output, advance time, make a nondeterministic choice,
   persist state, release a resource, or respond to the observed result have no owner before use.
   Acquiring a stream, event, handle, or resource does not own interpretation or response. Trace
   how tool/data/configuration files are created, edited, saved, and invoked. Treat every word in a
   capability id as binding semantic
   scope: its owner is the cumulative boundary, so fail any claimed component taught only later.
   Coverage-profile groups may be distributed across distinct capability ids, so a compound id is
   not justified by profile matching alone. For
   `externalWorkspace`, require the complete novice tool and delivery loop. Fail hollow
   late chapters, asset-generation shortcuts, or an unachievable `meta.description`. Media
   needs a licensed sourcing guide, exact placement, and a proof path that works without it.
8. **Learner construction.** Compare every learner-visible code block, exercise solution,
   starter, and any exceptional `artifactStep` with the reconstructed canonical project and hidden
   `referenceSteps`. Fail the course if any visible material supplies production-ready project
   structure/source/configuration/data/tests/maps/docs/asset placement/packaging/delivery, a
   ready-to-paste patch, a filled record, an answer-bearing test, or a rename-equivalent
   implementation. Also fail a learner-facing runtime starter containing anything beyond a blank
   editor file or unavoidable behavior-free tool metadata, even when it does not overlap the final
   solution. Every section's Working must make the learner create or assemble its real project
   changes. Beginner support may make requirements smaller and checks clearer, but may not transfer
   artifact ownership back to the lesson.
9. **Language mastery and transfer.** Starting level controls the entrance, not the exit. Preserve
   the selected objective hierarchy: Mastery 1 is project-first/minimum-language, Mastery 2 is
   project-first with general-language breadth, and Mastery 3–5 is language-first with the project
   as the practice/proof vehicle.
   Locate every structured `languageMastery.performance` and the Arc's `**Mastery proof:**`, then
   compare the learner-visible lesson
   path with the hidden `referenceSteps`. Confirm scaffolding actually fades to the plan's exact
   numbered `Mastery evidence` requirement. A completed reference project, cumulative replay,
   or elaborate final project proves solvability only. Verify every section's languagePractice is
   genuinely taught or retrieved and applied in its Working, and every performance Working has
   rubric rows covering the exact mapped language capabilities. Recheck the sealed foundation
   mapping: data, control, decomposition, failure, and verification must name distinct idiomatic
   language mechanisms rather than framework features. For Finish 3–5, structured abstraction and
   modularity must also map to concrete language idioms, `errors = CAN`, and the combined
   late-performance rubrics must cover every declared language capability. Recheck the Phase-1
   cadence against actual owners: every mapped foundation must be owned by the Arc midpoint,
   learner-authored verification must be owned no later than the section after decomposition, and
   representative later Workings must retrieve it. Hidden proof replay does not count. Each
   performance must
   map only capabilities materially exercised by its own novel task; fail indiscriminate full-spine
   mappings or unrelated requirements manufactured solely for coverage. Treat the final Working's
   full-spine `requires` as cumulative graduation evidence, distinct from its performance's natural
   subset. For Finish 3, require at least two late graded language performances across the course,
   including the final Working: each must demand a novel extension, integration, or diagnosis
   from specifications and observable checks without exposing its exact implementation or a
   rename-only twin. At least one must grade a recorded rationale. Fail a course that gives any
   canonical implementation in lesson material, or gives the decisive integration and then
   grades only a receipt, framework behavior, or trivial project route without language evidence.
10. **Evidence semantic congruence.** For every sealed capability, compare its declared label with
    the concept, worked example, exercise prompt/action, and learner-visible path that supposedly
    teaches and practices it. For every sealed performance, compare the public requirement,
    scenario contract, cognitive task, context distance, withheld help, and rationale demand with
    what the learner actually does. Fail label-only coverage, indiscriminate full-spine mappings,
    trivial renames, hidden architecture, or claims broader than the observed work. Answer directly
    whether a learner following the original prompt and visible path can build the promised result
    independently—not merely whether the reference project passes.

Record that audit in `.tome-build/BUILD_ID.mastery-semantic-review.json` using the exact §10
schema. Include every capability and performance in sealed order, cite concrete evidence, record
each repaired finding, and leave `unresolvedFindings` empty. Run
`python3 tools/validate_mastery_review.py BUILD_ID CURRENT_TOME`; the harness, not the reviewer,
derives PASS from this receipt plus executable evidence.

Resolve behavior from the approved arc, `meta.description`, acceptance journey, and runtime,
not majority wording. Repair any authored file or selected runtime. Proof-v1 PASS is derived
from executed evidence, never from your own prose claim. Repeat the strict and live commands
after every review repair and mark Phase 8 complete only when both remain clean.
