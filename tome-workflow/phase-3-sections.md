# Phase 3 — Sections (the course)

Read `tome-workflow/support/section-author.md`, then author every section in Arc order.
Work one complete section at a time: brief, lessons and exercises, then the cumulative
freestyle. Each section must add its promised capability to the same evolving project,
and no exercise or capstone may require something that this or an earlier lesson has not
actually taught.

One-worker mode keeps one warm session across Arc: execute and repair each section's code gate and
assigned quality window before advancing. Split mode uses one bounded warm batch. Reopen disk
checkpoints—not conversational memory—when reusing contracts. The harness repeats
the executable and final cross-section gates after the warm worker returns. If that process ends,
a replacement receives only sections that still fail authored-completion/handoff checks. Once all
sections are complete, any remaining whole-tome blocker gets a repair-only reconciliation pass;
recovery never wipes the section tree.

Use the plan's exact learner calibration and the `[narrative]` voice. Search all earlier
sections—not merely the immediately previous one—before changing a recurring type, file,
API, asset, or workflow. Preserve canonical contracts, retire temporary scaffolding at the
promised transition, and keep exercise feedback aligned with the final code.

After all sections are authored, perform the semantic reconciliation in
`tome-workflow/support/phase-3-reconcile.md` only when the harness assigns that repair pass.
A clean complete Phase-3 gate skips the extra worker. The validator supplies mechanical
counts and schema failures; fix its exact report rather than writing manual tallies into the
plan.

Produce the complete `sections/<sid>/` tree. Do not append a phase narrative or audit log
to the build plan.
